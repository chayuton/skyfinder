# ดาวนำทาง — Sky Finder

แอปดูดาวภาษาไทย ใช้พิกัดของเครื่องคำนวณตำแหน่งดวงอาทิตย์ ดวงจันทร์ ดาวเคราะห์
และดาวฤกษ์ 240 ดวงแบบเรียลไทม์ พร้อมผังกลุ่มดาว 40 กลุ่มที่วาดตามมุมเอียงจริงบนฟ้า
และปฏิทินล่วงหน้า 60 คืนที่บอกว่าคืนไหนฟ้ามืดพอจะเห็นดาวจาง

Flutter · Dart · ออกได้ทั้ง Android, iOS, Web, Windows, macOS, Linux จากโค้ดชุดเดียว

![build](https://github.com/chayuton/skyfinder/actions/workflows/ci.yml/badge.svg)

## สถานะการทดสอบ

ทุก commit บน `main` จะถูกคอมไพล์จริงบน GitHub Actions ด้วย Flutter stable
(ปัจจุบัน 3.47.7 / Dart 3.13.5) สี่งาน:

| งาน | เครื่อง | ตรวจอะไร |
|---|---|---|
| วิเคราะห์โค้ดและรันเทสต์ | ubuntu | `flutter analyze` ต้องไม่มี error และเทสต์ 209 ข้อต้องผ่าน |
| สร้าง APK | ubuntu | `flutter build apk --release` แล้วเก็บไฟล์เป็น artifact |
| สร้างเว็บ | ubuntu | รัน `tool/vercel_build.sh` ซึ่งเป็นสคริปต์เดียวกับที่ Vercel ใช้ แล้วตรวจว่าผลลัพธ์เป็นหน้าภาษาไทยที่ติดตั้งลงโฮมได้ |
| สร้าง iOS | macOS | `flutter build ios --release --no-codesign` |

### ดาวน์โหลด APK โดยไม่ต้อง build เอง

ไปที่แท็บ **Actions** ของ repo → เลือก run ล่าสุดที่เป็นสีเขียว →
เลื่อนลงไปที่ **Artifacts** → ดาวน์โหลด `skyfinder-apk`
แตกไฟล์แล้วได้ `app-release.apk` ก๊อปไปที่มือถือ Android แล้วกดเปิดได้เลย
(ต้องเปิด "อนุญาตติดตั้งจากแหล่งนี้" ก่อน)

ส่วน `skyfinder-web` คือเว็บแอปที่พร้อมอัปขึ้น Vercel, Netlify หรือ GitHub Pages

## เปิดบนเบราว์เซอร์ และ deploy ขึ้น Vercel

เว็บคือทางที่ครอบคลุมทุกระบบปฏิบัติการที่สุด: iPhone, Android, Windows, macOS,
Linux, ChromeOS เปิดลิงก์เดียวกันได้หมด และ**ติดตั้งลงหน้าจอโฮมเป็นแอปได้ด้วย**

### เชื่อม Vercel

1. ไปที่ [vercel.com/new](https://vercel.com/new) เข้าด้วยบัญชี GitHub
2. เลือก repo `skyfinder`
3. กด **Deploy** โดยไม่ต้องตั้งค่าอะไร — `vercel.json` ในโปรเจกต์บอกไว้หมดแล้ว

Vercel จะรัน `tool/vercel_build.sh` ซึ่ง**ติดตั้ง Flutter SDK ให้เองในขั้นตอน build**
เพราะเครื่อง build ของ Vercel ไม่มี Flutter มาให้ ครั้งแรกใช้เวลาราว 4–6 นาที
ครั้งถัดไปเร็วกว่าถ้า cache ยังอยู่

ตั้งแต่นั้นทุกครั้งที่ `git push` Vercel จะ build และอัปเดตให้เอง
push ขึ้น branch อื่นจะได้ลิงก์พรีวิวแยกโดยไม่กระทบตัวจริง

สคริปต์เดียวกันนี้ถูกรันใน CI ทุก commit ด้วย โดยชี้ `FLUTTER_HOME` ไปที่ Flutter
ที่ runner มีอยู่แล้ว **เส้นทาง deploy จริงจึงถูกทดสอบทุกครั้ง** ไม่ใช่แค่คำสั่งที่คล้ายกัน

### ติดตั้งลงมือถือจากเว็บ

* **Android (Chrome)** — เมนูสามจุด → **ติดตั้งแอป**
* **iPhone (ต้องใช้ Safari)** — ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**

ได้ไอคอนเข็มทิศบนหน้าจอโฮม เปิดเต็มจอไม่มีแถบเบราว์เซอร์ และ Flutter สร้าง
service worker ให้อยู่แล้ว จึงเปิดได้แม้ไม่มีสัญญาณหลังจากโหลดครั้งแรก
ซึ่งสำคัญ เพราะที่ที่ฟ้ามืดพอจะดูดาวมักไม่มีสัญญาณ

### เว็บทำอะไรได้ไม่เท่าแอปเนทีฟ

GPS ใช้ได้ปกติบนเว็บ แต่**เข็มทิศกับเซ็นเซอร์เอียงเข้าถึงยากกว่า** iOS ต้องให้ผู้ใช้
กดอนุญาตก่อน และบางเบราว์เซอร์ไม่ให้เลย ถ้าโหมดเล็งไม่ขยับบนเว็บ ให้ใช้แถบเลื่อน
"ปรับเอง" แทน หรือใช้ APK/แอป iOS ซึ่งเข้าถึงเซ็นเซอร์ได้เต็มที่

### ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `vercel.json` | บอก Vercel ว่า build อย่างไร เอาผลจากไหน และตั้ง cache header |
| `tool/vercel_build.sh` | ติดตั้ง Flutter แล้ว build เว็บ |
| `web_overlay/` | manifest, ไอคอน และ favicon ของเรา ทับของ Flutter |
| `tool/patch_web.py` | แก้ `index.html` ที่ Flutter สร้าง ให้เป็นภาษาไทยและติดตั้งลงโฮมได้ |
| `tool/check_web_output.py` | ตรวจว่าผล build เป็นของเราจริง ไม่ใช่หน้าเปล่าของ Flutter |

`index.html` ใช้วิธี**แก้ของที่ Flutter สร้าง** ไม่ใช่เขียนทับทั้งไฟล์ เพราะ Flutter
ฝัง bootstrap script ที่เปลี่ยนไปตามเวอร์ชัน SDK ถ้าเขียนทับจะพังวันที่ SDK อัปเดต

## เริ่มพัฒนา

```bash
git clone https://github.com/chayuton/skyfinder.git
cd skyfinder
./tool/prepare_platforms.sh     # สร้าง android/ ios/ web/ พร้อมใส่สิทธิ์ให้
flutter pub get
flutter test                    # ยืนยันว่าคณิตศาสตร์ถูกต้อง
flutter run
```

`tool/prepare_platforms.sh` คือสคริปต์เดียวกับที่ CI ใช้ มันเรียก `flutter create`
แล้ว**ใส่สิทธิ์ GPS กับเซ็นเซอร์ให้อัตโนมัติ** ทั้ง `AndroidManifest.xml` และ `Info.plist`
เพราะ `flutter create` เปล่า ๆ จะสร้างโปรเจกต์ที่ build ผ่านแต่หาตำแหน่งไม่เจอเงียบ ๆ
และยังลบไฟล์เทสต์ตัวอย่างที่ `flutter create` แถมมา ซึ่งอ้างคลาสที่โปรเจกต์นี้ไม่มี

โฟลเดอร์แพลตฟอร์มจึงไม่ถูก commit ลง repo โดยตั้งใจ — สคริปต์สร้างใหม่ได้เสมอ
และจะไม่ล้าสมัยตามเวอร์ชัน Flutter

### build แต่ละแพลตฟอร์ม

```bash
flutter build apk --release        # Android
flutter build appbundle --release  # สำหรับ Play Store
flutter build ipa                  # iOS, ต้องมี Mac + Xcode + บัญชี Developer
flutter build web --release        # เว็บ
```

## ชุดทดสอบ

`test/engine_test.dart` มี 209 assertion แบ่งเป็นสี่กลุ่ม:

1. **ตัวอย่างอ้างอิงของ Meeus** — ดวงจันทร์ตัวอย่าง 47.a และดวงอาทิตย์ 25.b
   ซึ่งเป็นค่ามาตรฐานที่ตำราดาราศาสตร์ใช้ตรวจสอบโปรแกรม
2. **การแปลงพิกัดและค่าคงที่** — ใจกลางทางช้างเผือก ขอบฟ้ากดลง ชื่อทิศ
3. **มุมเอียงผังกลุ่มดาว** — ต้องเท่ากับมุมพารัลแลกติกเชิงทฤษฎี ถ้าเครื่องหมายกลับด้าน
   ผังทุกกลุ่มจะเป็นภาพกระจก ซึ่งแย่กว่าไม่มีผังเลย
4. **ค่าจริง 5 สถานที่** — กรุงเทพฯ เชียงใหม่ ดอยอินทนนท์ เกาะหลีเป๊ะ หนองคาย
   เทียบตำแหน่งวัตถุทั้ง 9 ดวง เวลาขึ้น-ตก และแสงสนธยา ยอมคลาดได้ 1e-6 องศา

ค่าคาดหวังทั้งหมดมาจากการคำนวณล่วงหน้า ไม่ใช่จากตัวโค้ดเอง จึงเป็นการตรวจจริง
ไม่ใช่การยืนยันตัวเอง

`test/calendar_test.dart` ตรวจปฏิทินจันทร์ดับแยกอีกชุด โดยเทียบกับค่าที่
**หน่วยงานอื่นเผยแพร่** ไม่ใช่ค่าที่โค้ดนี้คำนวณเอง: เวลาจันทร์ดับ 7 ครั้ง
จาก US Naval Observatory กับตารางของ Fred Espenak, ตัวอย่าง 49.a ของ Meeus
(จันทร์ดับปี 1977 ซึ่งใช้คนละชุดสูตรกับที่แอปใช้), และความยาวเดือนจันทรคติ
สั้นสุด–ยาวสุดในกรอบปี 2026–2028

ค่ายอมรับตั้งไว้ที่ 2 นาที เพราะ USNO กับ Espenak เองยังต่างกัน 1 นาที
ในบางครั้ง ถ้าเทสต์ไม่ผ่านแปลว่าการค้นหาเพี้ยน **อย่าขยายค่ายอมรับให้ผ่าน**

### เรื่องเซ็นเซอร์

แอปไม่พึ่ง stream ที่ให้ค่ามุมมาสำเร็จรูป แต่อ่าน **ความเร่งกับสนามแม่เหล็ก**
ซึ่งเป็นเซ็นเซอร์ที่มือถือทุกเครื่องมี แล้วสร้างเมทริกซ์การหมุนเอง
(H = m × a คือทิศตะวันออก, M = a × H คือทิศเหนือ) วิธีนี้ตรงกับที่
`SensorManager.getRotationMatrix` ของ Android ทำ

จุดละเอียดที่ซ่อนอยู่: ตอนถือมือถือแบนราบ กล้องหลังชี้ลงพื้น ค่าทิศจากแกนนั้นจะสะบัด
โค้ดจึงเลือกอ่านจากขอบบนของเครื่องแทนเมื่อถือแบน และกลับไปอ่านจากกล้องหลังเมื่อยกขึ้นฟ้า

## ความแม่นยำ

* ดวงจันทร์ (ELP2000 ฉบับย่อ) ตรงกับตัวอย่าง 47.a ของ Meeus ถึงทศนิยมที่ 6
* ดวงอาทิตย์ ตรงกับตัวอย่าง 25.b คลาด 1e-5 องศา
* ดาวเคราะห์ ใช้ธาตุวงโคจรโดยประมาณของ JPL แม่นระดับลิปดาในช่วงปี 1800–2050
* ดวงจันทร์แก้ค่าพารัลแลกซ์ตามตำแหน่งผู้สังเกต ซึ่งคลาดได้ถึง 1 องศาถ้าไม่แก้
  (กว้างเท่าดวงจันทร์สองดวงเรียงกัน)
* มุมเงยรวมการหักเหของบรรยากาศ และขอบฟ้ากดลงตามความสูงของจุดสังเกต
  ที่ยอดดอยอินทนนท์ขอบฟ้ากดลง 1.48 องศา ทำให้ดวงอาทิตย์ตกช้ากว่าในเมืองราว 6 นาที
* ตำแหน่งดาวฤกษ์เลื่อนตามการหมุนควงของแกนโลกถึงวันที่ปัจจุบัน
* เวลาจันทร์ดับตรงกับ USNO และ Espenak ภายใน 1 นาที หาโดยไล่หาจุดที่ลองจิจูด
  ปรากฏของดวงจันทร์เท่าดวงอาทิตย์ ไม่ได้ลอกสูตรบทที่ 49 ของ Meeus มาอีกชุด

## ปฏิทินคืนฟ้ามืด

แท็บ "คืนนี้" มีปฏิทิน 60 คืนข้างหน้า ให้คะแนนแต่ละคืนจากสัดส่วนของชั่วโมง
ฟ้ามืดสนิทที่ดวงจันทร์ไม่รบกวน สองจุดที่ตั้งใจทำต่างจากแอปทั่วไป:

* **แสงจันทร์ไม่แปรผันตรงกับส่วนสว่าง** จันทร์ครึ่งดวงสว่างราว 9% ของจันทร์เพ็ญ
  ไม่ใช่ 50% เพราะทั้งพื้นที่สว่างลดลงครึ่งหนึ่งและอัตราส่วนสะท้อนแสงตกลงมาก
  เมื่อผิวดวงจันทร์บังเงาตัวเอง โค้ดจึงถ่วงด้วย `illum^2.4` ถ้าถ่วงเป็นเส้นตรง
  จะตัดคืนจันทร์ครึ่งดวงที่ใช้งานได้จริงทิ้งไปหมด
* **นับจากเวลาจันทร์ขึ้น-ตกจริง ไม่ใช่จากส่วนสว่างอย่างเดียว** จันทร์ข้างขึ้น 35%
  ตกหัวค่ำ เหลือคืนมืดเกือบทั้งคืน ส่วนจันทร์ข้างแรม 34% ขึ้นดึกแล้วค้างจนสว่าง
  ทั้งที่ส่องเท่ากัน สองคืนนี้ต่างกันคนละเรื่อง

ปฏิทินนี้คิดเฉพาะดวงจันทร์กับแสงสนธยา **ไม่รวมเมฆ ฝน หรือฝุ่น** ซึ่งในไทย
เป็นตัวตัดสินจริงว่าจะได้ออกไปดูหรือไม่

## ข้อจำกัดของข้อมูลสถานที่

NARIT และ ททท. ประกาศเขตอนุรักษ์ท้องฟ้ามืดรวมกว่า 79 แห่ง แต่**ไม่มีหน่วยงานใด
เผยแพร่พิกัดตัวเลขรายแห่ง** ในแอปจึงใส่เฉพาะแห่งที่หาพิกัดจากแหล่งอ้างอิงได้
และกำกับว่า "ค่าประมาณระดับพื้นที่" กับแห่งที่ยังไม่ยืนยัน
คลาดสัก 1–2 กม. ไม่มีผลต่อการคำนวณดาว แต่มีผลตอนขับรถไปหา

ทะเบียนเขตท้องฟ้ามืดมีอายุ 3 ปี รายชื่อจากปี 2565 บางแห่งอาจหมดสถานะแล้ว
